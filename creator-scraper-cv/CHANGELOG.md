# Navos 专用版 Skill 更新日志

> 本文档记录 `creator-scraper-cv` 单源码内 common / Navos runtime profile 的功能差异和版本更新。
>
> 维护方式：每次发布新版本时，在顶部新增版本块，记录用户可感知的功能变化。

---

## v1.9.7 - 2026-08-28

### 新增能力

#### 结构化达人搜索支持批量精确查询
- TikTok、Instagram、YouTube 结构化搜索新增 `union_user_ids` 与 `profile_urls` 两个可选列表参数，每个列表最多 200 条。
- 两种标识可单独使用或同时传入；同时传入时合并命中，并可继续叠加地区、粉丝量、联系方式等原有筛选条件。
- Skill 会校验这两个列表的格式与数量，避免无效请求；外部 OpenAPI 文档同步补充参数说明。
- 明确数量请求的分页策略：未说明数量时默认请求 20 条；明确要求 N 条时当前页请求 `min(N,100)`；超过 100 条时只返回第一页并在继续分页前征得确认，避免 `size > 100` 触发生产接口校验错误。

## v1.9.6 - 2026-08-21

### 问题修复

#### 视频审核失败时能看到具体原因
- 视频审核任务失败时，会明确告知失败原因（例如链接平台不支持、视频超过 10 分钟、文件超过 500MB、视频已删除或设为私密），不再只回复一句「分析失败」。
- 提交不支持的视频链接时，会在提交前就指出问题并说明正确的链接格式，不再等几分钟后才失败，也不再消耗积分。
- 常见误传链接会给出针对性提示：YouTube 长视频页（`watch?v=`）只支持 Shorts、TikTok 分享短链需要换成完整链接、抖音不在支持范围。
- 各类接口错误（积分不足、当日配额用尽、权限不足）的原因现在也能稳定传达到对话中，此前在部分运行环境下会丢失。

#### 视频审核提交参数与服务端对齐
- 修复视频审核两条提交链路的参数不匹配问题：社媒链接审核与上传素材审核此前都可能因参数名不一致而提交失败。
- 上传素材审核改为使用上传接口返回的完整素材地址（`oss_url`），不再使用素材 key。旧参数名 `url`、`oss_url_override` 仍可继续使用。

### 说明
- 视频审核支持的链接范围不变：TikTok 视频、YouTube Shorts、Instagram Reels。
- 其余能力（结构化找达人、自然语言找达人、竞品品牌找达人、品牌视频洞察、假粉检测、批量采集、导出、建联）保持不变。

## v1.9.4 - 2026-07-30

### 体验优化

#### Navos 更新：找达人过程更像业务助手
- 达人搜索前会先判断需求是否足够清晰；如果用户没有说明平台、目标地区、品类方向等关键信息，会先做一轮简短 brief 澄清，再开始匹配，减少默认猜平台导致的结果偏差。
- 搜索过程不再向用户暴露参数、字段名、接口名、页码、服务等级、召回类型等技术细节，改为用业务语言确认匹配条件和执行边界。
- 当严格条件命中不足时，会直接说明当前命中数量，并给出可放宽的方向，不再为了凑数自动跨平台、自动翻页或返回不匹配达人。
- Navos 对话区的结果输出更聚焦：保留结果摘要、达人表格、少量业务判断、CreatiVault 查看入口和下一步建议，减少冗长解释和前后矛盾。
- 搜索结果和快照列表的数量口径以本次实际返回达人为主，不再把库内候选总量包装成已匹配数量；展示文案更靠近“Navos 已为您匹配 X 个达人，点击下方卡片可查看达人深度画像数据”。

#### Navos 更新：语言和内置浏览器体验更贴近用户
- Skill 会读取 Navos 客户端语言设置，国内中文用户默认使用中文口径，海外英文用户默认使用英文口径；读取不到设置时兜底英文。
- 建联发送、任务查询、沟通历史和待办场景中的 CreatiVault 入口会使用更适合 Navos 内置浏览器的紧凑布局，方便在半屏窗口里查看建联过程和邮件内容。
- 对话区中的 CreatiVault 列表和建联入口继续使用短链接展示，避免把很长的授权链接直接暴露给用户。

#### 通用更新：安装和环境口径更清晰
- `creator-scraper-cv` 统一发布到 `main` 分支，普通用户和 Navos 用户不再需要区分专用分支安装；安装后由 Skill 自动识别 common、Navos 国内版和 Navos 海外版运行环境。
- 生产 API 默认入口统一调整为稳定的 Skill 网关地址；测试或开发环境需要显式配置测试 API 地址，避免误连生产或泄露内网域名。
- 保持结构化达人搜索、自然语言找达人、竞品品牌找达人、品牌视频洞察、假粉检测、批量采集、导出和建联等既有能力不变。

## v1.9.2 - 2026-07-16

### 新增能力

#### Navos 更新：无感登录并打开 CV 原生达人详情
- 达人搜索结果新增 `cv_list_url`：Navos 内置浏览器会通过结果列表票据自动建立真实 Logto Session，并打开本次 OpenAPI 搜索结果快照列表；列表默认保留 90 天，复用 CV 找达人原生展示和详情弹窗。
- Navos 用户无需设置或输入 CV 密码；每次打开会换取一个短期 Logto one-time-token 启动 passwordless 登录，最终登录态仍由 CreatiVault 标准 OIDC callback 写入 CV 域 Cookie。
- 已有且属于同一 Navos 用户的 CV Session 会直接复用；没有 Session 或内置浏览器无状态时，会自动完成一次无感换票登录。
- 搜索结果快照默认保存 90 天，登录票据仍保持短期有效；用户之后从 Navos 对话回看列表时，展示的是已计费搜索快照，不会因为打开列表再次触发 OpenAPI 搜索计费。
- 登录成功后复用 CreatiVault 现有找达人列表和达人详情弹窗组件，不再由 Skill 或 Navos Artifact 重复实现详情 UI。

#### 通用更新：品牌视频洞察检索
- 新增品牌视频洞察检索能力，支持用户输入品牌名或竞品名后，在 CreatiVault 已收录视频库中查找相关视频内容。
- 复用 SaaS「关键词监控」中的 Hashtag 扩展逻辑，默认将品牌名扩展为 5 个相关检索词，但不改变关键词监控页面原有的扩展行为。
- 品牌视频洞察只检索已有视频库，不会自动触发实时采集；如果已有库没有结果，会先说明未命中，再由用户确认是否启动实时品牌提及采集。
- 视频检索接口的 Hashtag 上限从 3 个调整为 5 个，便于品牌洞察、话题组合和素材检索场景覆盖更多关键词。
- 品牌洞察结果会展示实际使用的扩展词、命中视频、匹配 Hashtag、平台分布、热门标签和高频达人，帮助用户判断品牌内容热度、竞品内容表现和可参考素材。

#### Navos 更新：品牌洞察展示更清晰
- Navos 中用户提出“看某品牌相关视频”“竞品品牌视频洞察”“Fenty Beauty 有哪些热门内容”等需求时，优先使用品牌视频洞察检索，不先走公开网页搜索。
- 展示结果时先给出检索摘要和扩展词，再用视频表格展示平台、视频标题、匹配词、播放量、点赞、评论、互动率、达人、发布时间和视频链接。
- 当没有命中已有视频时，不静默切换普通视频搜索、不自动采集，而是提示用户当前已有库没有结果，并询问是否继续做实时品牌提及采集。
- 保持品牌合作达人查询、结构化达人搜索、自然语言搜索、假粉检测、Navos 国内/海外身份识别和余额预检能力不变。

- Navos 默认 S3 搜索结果不再拆成“基础表 + 受众画像表”两张表，改为一张动态宽表承载同一批达人，减少用户上下对照成本。

- 头像作为 S1 基础字段独立展示，使用 40px 等比例缩略图渲染；头像缺失时留空，不再只展示文字链，也不编造占位图。
- Navos 场景下不再生成单个达人 单个达人详情链接，统一通过 `cv_list_url` 打开 CreatiVault 原生搜索结果列表；用户在列表中点击达人即可打开 SaaS 原生详情弹窗，平台主页链接仍作为单独入口保留。
- 自然语言搜索返回的是固定精简字段，不套用 Navos S3 宽表规则；如用户需要完整联系方式或受众画像，需要切换到结构化搜索。

#### 通用更新：版本与展示口径同步
- 更新 skill 版本到 `1.9.1`，同步发布 manifest，便于安装端检测到最新版本。

- Navos 场景下不再生成单个达人 单个达人详情链接，统一通过 `cv_list_url` 打开 CreatiVault 原生搜索结果列表；用户在列表中点击达人即可打开 SaaS 原生详情弹窗，平台主页链接仍作为单独入口保留。
- 保持 common、Navos 国内版、Navos 海外版现有授权、余额预检、语言偏好和品牌找达人能力不变。

#### 通用更新：品牌视频洞察检索

- `/openapi/v1/videos/search` 的 `hashtag` 上限同步调整为 5 个；品牌洞察场景仍优先使用新接口，因为新接口会按单个 Hashtag 分别检索并合并去重。
- 结果会返回实际使用的扩展词、命中视频、平台分布、热门标签和热门达人，适合做品牌内容热度、竞品内容表现和素材线索判断。

## v1.9.0 - 2026-07-14

### 新增能力

#### 通用更新：竞品品牌找达人
- 新增竞品品牌合作达人发现能力，支持用品牌名查找 CreatiVault 已沉淀的合作达人记录。
- 离线查询优先返回已确认的品牌合作关系，包含合作达人、匹配到的品牌账号以及可用于判断合作关系的证据视频。
- 当离线库暂时没有结果时，不再静默切换到普通达人搜索或公开网页搜索，而是明确提示当前未找到已沉淀记录，并询问是否启动实时品牌提及采集。
- 新增轻量实时品牌提及采集能力，可通过品牌名或关键词发起平台内容采集，用于发现可能提到竞品品牌的候选达人和内容线索。
- 明确实时采集结果属于“候选线索”，不等同于离线确认过的品牌合作记录；展示时必须区分“已确认合作达人”和“品牌提及候选达人”。
- 支持 TikTok / Instagram 品牌合作达人发现链路，帮助业务在竞品分析、达人拓展、品牌合作名单搭建时更快找到可参考对象。

#### Navos 更新：品牌找达人链路更稳
- Navos 场景中，用户提出“找某品牌合作过的达人”“竞品品牌达人”“Fenty Beauty 合作达人”等需求时，优先调用 CreatiVault 官方达人库和品牌合作数据，不先走网页搜索。
- 离线品牌合作记录为空时，先向用户说明没有已沉淀合作记录，再由用户确认是否启动实时采集，避免静默查询带来额外积分消耗。
- 实时采集任务会清楚说明当前返回的是品牌提及候选线索，避免把普通提及误认为已确认合作。
- 保持 Navos 国内/海外身份、语言和余额预检逻辑不变，品牌找达人能力复用现有授权与计费链路。

## v1.8.9 - 2026-07-09

### 新增能力

#### OpenAPI v2.1：自然语言搜索达人
- 新增 `scripts/search_creators_nl.mjs`，通过一句自然语言在 Instagram、TikTok、YouTube 单平台搜索达人。
- Instagram 支持内容主题、达人画像、内容风格和商业适配的语义向量召回；语义不足时由服务端在同一次请求内自动 fallback 到标量检索。
- TikTok 和 YouTube 支持自然语言解析后的标量检索。
- 脚本严格只发送 `query`、`platform`、`limit`，避免 Navos profile 自动注入该接口不支持的 `lang` 或内部调参字段。
- 补充自然语言搜索与结构化搜索的选择规则；邮箱、更新时间、完整 S3 字段等强约束仍使用结构化搜索。
- 明确自然语言搜索固定消耗 15 credits/次，与 `limit`、实际返回数量和召回类型无关。
- Instagram 的服务端 `scalar_fallback` 属于同一次请求，不会重复计费。
- 多平台搜索按平台分别调用并分别计费，执行额外平台前必须提示用户确认。
- Navos 调用前按 15 credits 执行余额预检，余额不足时不发送 OpenAPI 请求。

#### OpenAPI v2.2：达人假粉检测
- 新增 `audit/fake-follower-audit/SKILL.md` 和 `scripts/fake_follower_audit.mjs`，支持通过达人主页链接或平台与达人标识检测 TikTok、Instagram、YouTube 达人的假粉和互动质量风险。
- 返回假粉率估算、互动质量分、风险等级、异常类型、检测信号以及可用的达人与受众画像。
- 国内 Navos 默认返回中文结论，海外 Navos 和 common 默认返回英文结论，也可通过 `lang` 显式指定。
- 假粉检测保持后端默认 S1，不继承 Navos 结构化达人搜索的 S3 自动注入。
- 计费跟随后端 `/openapi/v1/fake-follower-audit/run` 动态规则，不在 Skill 中写死 credits。
- 增加部分结果、风险等级和百分比口径的强制解释规则，避免把估算值描述为平台官方审计结果。

## v1.8.8 - 2026-07-07

### 体验优化

#### Navos 海内/海外运行区分
- 仅保留 `navos-cn` 与 `navos-global` runtime profile，不再发布旧 `navos` profile 文件。
- 自动读取 Navos identity 文件中的 `app_id`：`navos-cn` 走国内版，`navos-global` 走海外版；取不到 `app_id` 时默认海外版。
- 国内版默认 `lang=cn`，海外版默认 `lang=en`；OpenAPI 主域名保持不区分海内外。
- 国内/海外版分别使用 `partner_code=navos-cn` / `partner_code=navos-global`，并在 OpenAPI 请求中透传同名 `X-Source`；旧 `navos` 继续兼容历史 API Key。
- Skill profile 不再维护 Navos 校验/回调域名；CV 后端统一从 `open_api_partners` 按 `partner_code` 读取 `validate_url` / `credits_callback_url`。
- 余额预检域名按 `navos_region` 内置映射选择：国内走 `navos-mind-server-vip-gz.tec-do.com`，海外走 `navos-mind-server-vip.tec-do.com`。

### 问题修复

#### 优化达人搜索列表展示
- 头像列改为等比例缩略渲染，固定展示区域但不拉伸图片，避免竖图或横图被 `36x36` 硬压缩变形。

- Navos 默认 S3 场景不再使用固定表头；展示列会按接口实际返回字段动态生成，覆盖 S1 + S2 + S3 的全部可读字段。`AI`、`带货` 等属性列仅在响应真实返回且有有效值时展示，不再出现空白固定列。
- 下一步建议中的建联推荐改为确定性规则：用户表达合作/联系意图时必须给建联建议；有 2 个及以上邮箱达人时建议批量建联，只有 1 个邮箱达人时建议单独建联，没有邮箱时改为继续筛有邮箱达人或导出/lookalike。

#### Navos 默认不再被 CV_API_KEY 环境变量覆盖
- Navos 专用版默认始终使用 Navos 登录态与 `~/.creativault/skill-credentials.json` 中的环境化缓存 key，避免用户机器上残留的 CV 平台 API Key 覆盖 Navos 授权链路。
- 仅开发排障时可显式设置 `CV_ALLOW_ENV_API_KEY=true` 临时启用环境变量覆盖；普通 Navos 用户无需配置，也不应依赖 `CV_API_KEY`。

#### 命中缓存时校验 Navos 登录态
- 新增 CV 后端包装接口 `/internal/partners/{partner_code}/users/validate`，只校验本地 `uid + token`，不签发、不创建、不返回 API Key。
- Skill 命中当前环境缓存时，会先调用该校验接口；若 Navos token 已失效，则清理当前环境、当前 uid 的本地缓存，并提示用户重新登录 Navos。
- 用户重新登录后再次使用时，因为本地缓存已清理，会重新调用 ensure；同一个 uid 在服务端映射命中时仍返回原 API Key，`is_new=false`。

#### 按环境隔离 Navos API Key 缓存
- 缓存 key 从 `navos:<uid>` 升级为 `navos:<skill_channel>@<cv_host>:<uid>`，避免 beta/staging 与 stable/prod 共用同一个缓存槽位。
- 用户升级后不需要手动删除旧的 `~/.creativault/skill-credentials.json`；旧缓存不会被新版本命中，首次使用对应环境时会自动重新 ensure 并写入新的环境缓存。
- 缓存内容新增 `skill_channel`、`cv_base` 元信息，便于排查当前 key 属于哪个环境。

#### 尊重 CV 鉴权状态
- 当业务接口返回 `40101` / `40102` / `40103` 鉴权错误时，客户端不再自动调用 ensure 重新签发，避免绕过 CV 侧对 API Key 的失效、过期或吊销控制。
- 如需恢复访问，应由 CV / Navos 服务端侧重新启用或签发，客户端仅负责读取当前环境对应缓存。
